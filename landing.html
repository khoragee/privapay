Features

Built for real
organisations.

Every feature designed around the principle that salary data should never be public.

🔒
01

Encrypted Salaries

All salary values stored as euint64 FHE ciphertexts. Mathematically indistinguishable from random noise to anyone without the key.

👤
02

Per-Employee ACL

Zama's Access Control List ensures only the employer and relevant employee can decrypt their salary. Enforced cryptographically.

📅
03

Payroll Periods

Employees claim once per period. Employers advance the cycle. Clean, auditable, and entirely onchain.

🔍
04

HR Band Checks

HR verifies salary compliance without seeing exact amounts. Result is an encrypted boolean — only HR can decrypt.

📊
05

Encrypted Totals

Total payroll tracked as an encrypted accumulator. Audit without exposing individual salaries.

⚡
06

Batch Operations

Set salaries for entire teams in one transaction. Emergency pause/unpause. Built for enterprise scale.

How It Works

Four steps.
Zero leaks.

Every step of the payroll flow happens with encrypted data.

STEP 01

Employer encrypts salary

Amount encrypted client-side with Zama Relayer SDK. ZKPoK generated alongside the ciphertext.

input.add64(salary)
const enc = await input.encrypt()
// → handle + ZKPoK
STEP 02

Contract validates & stores

FHE.fromExternal() validates the ZKPoK. ACL set so only employer + employee can access.

euint64 s = FHE.fromExternal(
encSalary, inputProof
)
FHE.allow(s, employee)
STEP 03

Employee claims salary

Employee calls claimSalary(). Encrypted amount added to accumulator. No plaintext ever emitted.

_total = FHE.add(
_total,
_salary[employee]
)
STEP 04

Employee decrypts privately

Relayer SDK re-encrypts balance under personal key. Plaintext never leaves the device.

const salary = await instance
.reencrypt(handle,
privateKey, sig...)
Why FHE

Not ZK.
Not MPC.
FHE.

ZK proofs can prove a fact without revealing data but can't compute on persistent hidden state. MPC distributes trust but requires multiple online parties. FHE is the only approach that lets a single smart contract compute on encrypted state that persists across transactions.
